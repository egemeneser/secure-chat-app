# secure-chat-app

A secure end-to-end encrypted messaging prototype inspired by the cryptographic principles of the Signal Protocol.

The project focuses on secure key establishment, client-side encryption, and encrypted message exchange while keeping private cryptographic material on the client side.

## Overview

Secure Chat App is a client-server messaging application designed to explore modern end-to-end encryption mechanisms.

The server is responsible for user management, public key distribution, and encrypted message storage. Message encryption and decryption are performed on the client side, meaning that the server handles ciphertext rather than plaintext message content.

The project implements a pre-key-based key establishment architecture inspired by the Signal Protocol and explores post-quantum secure key exchange through Kyber-based PQXDH.

## Cryptographic Architecture

The application follows a pre-key-based key establishment model inspired by the Signal Protocol.

Each client maintains cryptographic key material used to establish secure communication with other users.

### Identity Keys

Each user owns a long-term identity key pair.

The private identity key remains on the client, while the corresponding public key can be published through the server as part of the user's key bundle.

Identity keys provide a persistent cryptographic identity for the user.

### Signed Pre-Keys

Clients generate signed pre-keys that are cryptographically signed using the user's identity signing key.

Ed25519 signatures are used to verify the authenticity of signed key material and reduce the risk of malicious key substitution.

### One-Time Pre-Keys

One-time pre-keys are generated by the client and uploaded to the server.

When another user initiates a secure conversation, one of these keys can be consumed as part of the initial key agreement process.

This allows secure sessions to be established even when the receiving user is offline.

### Key Agreement

The application uses Diffie-Hellman-based shared secret derivation with X25519 key material.

Multiple key agreement outputs can be combined and passed through a key derivation process to generate cryptographic key material for secure communication.

HKDF is used to derive keys from shared secret material.

The project also explores Kyber-based PQXDH to extend the initial key establishment process with post-quantum cryptographic protection.

## Message Encryption

Messages are encrypted on the sender's client before being transmitted to the server.

AES-256-CTR is used for symmetric message encryption.

HMAC-SHA256 provides message authentication and integrity verification.

The encrypted message is then sent to the server and stored as ciphertext.

The receiving client retrieves the encrypted message and performs decryption locally using the derived cryptographic key material.

Conceptually, the message flow is:

```text
Sender
   |
   |  Encrypt message locally
   v
Ciphertext
   |
   |  Send encrypted message
   v
Server
   |
   |  Store and deliver ciphertext
   v
Receiver
   |
   |  Decrypt message locally
   v
Plaintext
```

The server is not responsible for decrypting message content.

## Security Model

The application is designed around the following principles:

### End-to-End Encryption

Messages are encrypted before leaving the sender's client and decrypted by the receiving client.

### Private Key Isolation

Private cryptographic keys are not intentionally transmitted to the server.

### Authenticated Key Material

Ed25519 signatures are used to authenticate signed pre-key material.

### Encrypted Server Storage

The server stores encrypted message content rather than plaintext messages.

### Post-Quantum Experimentation

Kyber-based PQXDH is explored as an extension to classical Diffie-Hellman-based key establishment.

This allows the project to investigate hybrid key establishment mechanisms that combine classical and post-quantum cryptography.
